# Synthèse benchmark — points forts / faibles à appliquer

> Référencé par `NIHAO_05_PLAN_ACTION_COMPLET.md`. Synthèse marché agentique 2026.

## Points forts à appliquer dans NIHAO

| Brique | Inspiration marché | Application NIHAO |
|--------|--------------------|-------------------|
| Runtime | LangGraph (graphes, outils, HITL) | Runtime graphe + approvals CEO |
| Multi-agent | CrewAI / AutoGen | Équipes d’agents seed (11) + orchestration |
| Enterprise | Agentforce, Copilot Studio, ServiceNow | Modules métier + RBAC + audit |
| Knowledge | Glean / RAG | RAG hybride + mémoire multi-niveaux |
| Assistants | ChatGPT / Claude / Copilot | Chat assistant + AI Office |
| Distribution | AppExchange / GPT Store | Marketplace privé puis public |
| Cloud agents | Bedrock Agents | Abstraction multi-modèles |

## Points faibles à éviter

| Faiblesse marché | Contre-mesure NIHAO |
|------------------|---------------------|
| Fragmentation assistant vs builder vs marketplace | Une plateforme unifiée (OS) |
| UX enterprise opaque | Progressive disclosure : chat → studio → admin |
| Pricing quote-only illisible | Grille FREE / PRO / BUSINESS + packs modules |
| Lock-in cloud unique | Multi-modèles, multi-cloud ready |
| Pas de gouvernance | Permissions, guardrails, sandbox, eval |
| Pas de 3D natif « tout-en-un » | Stack : runtime + AI Office Three.js |

## Positionnement

NIHAO = **simplicité d’un assistant** + **puissance d’un framework** + **sécurité enterprise** + **scale marketplace**, avec AI Office 3D comme surface distinctive.
